# v1.0.0 路线图与技术规格

状态：**实施中**
产品定位：CLIProxyAPI (CPA) 的代理 API Key 管理与用量归因插件（插件 ID `cpa-secret-manager`）。

---

## 1. 背景与目标

官方 CPA 管理端可以增删改代理密钥（`/v0/management/api-keys`），但**不支持为密钥附加任何人工标注**，也不提供"按密钥"的 token 用量视图（官方 `/v0/management/api-key-usage` 是按上游凭证聚合的 success/failed，无 token、无模型）。

本插件补齐两个缺口：

1. 每把代理 API Key 可维护一条**备注**；
2. 每把代理 API Key 显示其**累计 token 用量与模型分类**。

同时保持与基座 `antigravity-priority` 一致的工程架构：CGO 插件 ABI 适配层、Runtime 应用层、原子落盘、零外部依赖嵌入式页面、本地 devserver、CI/Release 质量门禁。

---

## 2. 范围

### 2.1 功能

| 功能 | 说明 |
| --- | --- |
| 密钥列表 | 读取宿主 `api-keys`，默认掩码显示，支持单条显示/隐藏 |
| 新增密钥 | 手填或使用**官方同构算法**自动生成；生成后可复制 |
| 编辑密钥 | 修改密钥值（备注由页面显式迁移到新索引） |
| 删除密钥 | 二次确认后从宿主列表移除，并删除对应备注索引 |
| 备注 | 每把密钥一条备注，支持增改删；保存到插件状态文件 |
| 筛选 | 按密钥值或备注做大小写不敏感的包含匹配（**无名称字段**） |
| 用量 | 每把密钥的请求数、失败数、输入/输出/合计 token（累计）与模型数 |
| 模型明细 | 展开某把密钥，按模型显示请求数、失败数与 token 明细 |
| 设置 | `usage_enabled` 开关、状态文件路径展示、备注与用量统计的清理入口说明 |
| 主题 | 跟随宿主 CPA 主题（浅色 / 纯白 / 深色 / 自定义），iframe 内实时切换 |
| 语言 | 简体中文与英文；默认跟随宿主 `cli-proxy-language` |

### 2.2 非目标

不做：费用与价格估算、models.dev 同步、CSV / PNG 导出、数据库备份恢复、按时间窗口或趋势图、逐请求明细表、完整模式二次鉴权会话、名称字段、备注随宿主配置迁移、用量按时间桶重置、第三语言。

## 3. 架构

```
CPA 宿主进程
├── main.go                     C ABI 薄适配器（4 个导出符号 + JSON 信封）
├── internal/runtime            生命周期与用例编排、管理路由分发、刷盘节流
│   ├── internal/keys           密钥生成（官方算法 1:1）
│   ├── internal/remarks        备注索引（SHA-256）
│   ├── internal/usage          用量聚合与归因
│   └── internal/state          状态文档 + 原子落盘（唯一持久化入口）
├── internal/management         嵌入式 Web UI（纯字符串拼装，零外部 CDN）
└── data/cpa-secret-manager-cache.json
官方管理端 ── 同源 iframe ──► /v0/resource/plugins/cpa-secret-manager/keys
```

- **零 host 回调**：本插件不读写宿主凭证文件、不发起上游请求，因此不使用 `host.*` RPC。
- 插件能力声明：`{"management_api": true, "usage_plugin": true}`，`schema_version: 1`。

## 4. 接口契约

### 4.1 复用的宿主接口

| 方法与路径 | 用途 |
| --- | --- |
| `GET /v0/management/api-keys` | 读取密钥列表（`{"api-keys": [...]}`） |
| `PUT /v0/management/api-keys` | 全量替换列表（新增 / 编辑 / 删除） |
| `PATCH /v0/management/api-keys` | 按 `old/new` 或 `index/value` 单条修改（可选路径，本实现使用 PUT） |

均需管理密钥：`Authorization: Bearer <key>` 与 `X-Management-Key: <key>` 同时携带。

### 4.2 插件自有接口（宿主统一鉴权）

| 方法 | 路径 | 请求 | 响应 |
| --- | --- | --- | --- |
| POST | `/v0/management/plugins/cpa-secret-manager/resolve` | `{"keys": ["sk-...", ...]}` | `{"items": [{"hash", "remark", "usage": {...}}], "unattributed_requests", "orphan_remarks", "orphan_usage"}`，**items 与 keys 按序一一对应** |
| PUT | `.../remarks` | `{"key": "sk-...", "remark": "..."}` | `{"status": "ok"}`（备注为空串 = 删除） |
| POST | `.../remarks/delete` | `{"key": "sk-..."}` | `{"status": "ok"}` |
| POST | `.../keys/generate` | `{}` | `{"key": "sk-..."}` |
| GET | `.../settings` | — | `{"usage_enabled": true, "state_path": "..."}` |
| PUT | `.../settings` | `{"usage_enabled": false}` | `{"status": "ok"}` |

资源页（浏览器，无鉴权，纯静态）：`GET /v0/resource/plugins/cpa-secret-manager/keys`，菜单名 `API Key Manager`。

> 页面把当前密钥列表按序提交给 `resolve`，由插件在 Go 侧计算 `SHA-256` 返回按下标对齐的数据。这样页面**不依赖 `crypto.subtle`**（该 API 仅在安全上下文可用，`http://<局域网IP>:8317` 下不可用），局域网明文 HTTP 部署同样可用。

### 4.3 状态文件

```jsonc
{
  "schema_version": 1,
  "remarks": { "<sha256>": { "remark": "用于本地开发", "updated_at": "RFC3339" } },
  "usage": {
    "<sha256>": {
      "requests": 0, "failed": 0,
      "input": 0, "output": 0, "reasoning": 0,
      "cached": 0, "cache_read": 0, "cache_creation": 0, "total": 0,
      "first_seen": "RFC3339", "last_seen": "RFC3339",
      "models": { "<model>": { "requests": 0, "failed": 0, "input": 0, "output": 0,
                               "reasoning": 0, "cached": 0, "cache_read": 0,
                               "cache_creation": 0, "total": 0 } }
    }
  },
  "app_config": { "usage_enabled": true },
  "metrics": { "unattributed_requests": 0 }
}
```

- 权限 `0600`，写入走 `*.tmp` + `os.Rename`。
- 禁止出现密钥明文。

## 5. 关键算法

### 5.1 密钥生成（与官方管理端 1:1）

```
prefix = "sk-"   randomLen = 48   charset = [A-Za-z0-9] (62)
maxUnbiased = floor(256 / 62) * 62 = 248
取 crypto/rand 字节流；byte >= 248 丢弃；否则输出 charset[byte % 62]；凑满 48 位
结果固定 51 字符
```

### 5.2 用量归因

```
usage.handle(record)
  key := record.APIKey            // 客户端代理密钥（host: gin "userApiKey"）
  if key == "" → metrics.unattributed_requests++
  else → hash := SHA-256(key)
         usage[hash] += record.Detail（input/output/reasoning/cached/cache_read/cache_creation/total）
         usage[hash].models[record.Model] += 同上
         record.Failed → failed++
```

未知摘要（不在当前 `api-keys` 中）同样累计，但只在 `resolve` 里以 `orphan_usage` 计数呈现。

### 5.3 主题跟随

1. iframe 内：`getComputedStyle(window.parent.document.documentElement)` 抽取宿主生效的语义变量并覆盖到插件页根元素；`MutationObserver` 监听 `data-theme` / `class` / `style` 实时重放。
2. 独立打开：`cli-proxy-theme` → `prefers-color-scheme` → 手动 `window.setTheme()`。
3. 页面自带与官方同名的浅色 / 纯白 / 深色三套静态 Token 兜底。

## 8. 依赖与兼容

- 宿主最低版本：**v7.2.0**（该版本起存在 `sdk/pluginabi` 与 `usage_plugin` / `management_api` 能力，且 `UsageRecord.APIKey` 已为客户端密钥）；推荐使用当前最新版。
- 官方管理端 ≥ 7.2.147（插件菜单与资源 iframe）。
- 构建需要 Go + CGO + 平台 C 编译器，产物为动态库：`cpa-secret-manager.{so,dylib,dll}`。
