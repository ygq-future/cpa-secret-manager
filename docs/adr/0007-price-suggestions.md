# 0007: 参考价建议采用 models.dev 流式裁剪与显式同步

> 后续变更：模型名的分段前缀匹配与多报价下拉选择见 [ADR-0009](./0009-prefix-price-matching.md)。

## Context

v1.2 起插件支持按模型配置输入 / 输出 / 缓存单价（USD / 1M tokens），并据此计算消费配额。单价完全靠人工填写：运维需要自己查价、换算单位，模型一多就容易填错或漏填。设置页的模型列表又来自宿主实际出现过的模型，数量可控，因此"为当前模型列表补一个参考价"是一个自然的需求。

候选数据源：

- **models.dev `https://models.dev/api.json`**：约 5.9 MB，235 个 provider、约 9000 条模型条目；`cost.input` / `cost.output` / `cost.cache_read` 的单位正好是 USD / 1M tokens，与插件 `ModelPrice` 完全一致；同一模型常有多个 provider 报价（官方与转售商并存）。
- **OpenRouter `/api/v1/models`**：约 0.8 MB、465 条，体积小得多，但只覆盖 OpenRouter 上架的模型，价格是"每 token"字符串，且缺少大量官方 provider 的独立报价。
- **构建期快照**：零网络，但发布即过期，与插件"按需、可验证"的定位冲突。

需求约束：

1. 不能把整份目录读进内存再反序列化；5.9 MB JSON 在 Go 中容易放大成数十 MB 的临时对象。
2. 插件此前不发起任何外部网络请求。新增网络能力必须是**用户显式触发**的，不能在打开设置页时偷偷下载。
3. 参考价的写入必须由用户显式同步触发，不能在后台静默改写单价；同步时按固定合并规则处理：新增缺失、更新变化、忽略一致、保留参考价中已缺失的已保存模型。
4. 宿主可能没有外网；失败时必须保留已有缓存并给出可读错误。

## Decision

1. **数据源固定为 models.dev `api.json`**。URL 不接受用户输入；默认客户端带 20 秒超时、最多 3 次重定向、仅允许 HTTPS 重定向。`models.dev` 的单位与插件一致，省去换算与浮点误差。
2. **流式裁剪**。`internal/pricing.Decode` 用 `json.Decoder` 逐 token 遍历 provider → models；对未命中的模型直接 `skipValue`，不分配其值；命中的模型只解码 `id` / `canonical_model_id` / `last_updated` / `cost` 四个字段。峰值内存只与"命中的模型对象"和单个 JSON 值有关，与目录总大小无关。响应体有 32 MiB 上限。
3. **只缓存命中的结果**。独立文件 `prices.json`（默认 `data/cpa-secret-manager/prices.json`，旧布局为 `data/cpa-secret-manager-cache-prices.json`，见 ADR-0008）保存：来源、同步时间、ETag、上次请求覆盖的模型名（含未命中的 miss）、以及每个模型的紧凑 `Suggestion`。整份目录既不落盘也不常驻内存。该文件是**派生数据**，删除后下一次显式同步即可重建。
4. **显式同步，读路径零网络**。`POST /pricing` 只读缓存；`POST /pricing/refresh` 才下载目录。页面在"同步并保存参考价"按钮点击时才调用后者；打开设置页、切换模型、刷新列表都不会触网。缓存超过 7 天只标记为"已过期"，不自动刷新。
5. **条件请求与 known 集合**。缓存保存 ETag；当本次请求的模型集合是上次成功同步集合的子集时发送 `If-None-Match`，304 直接复用缓存。若出现新模型，则跳过条件头重新下载，避免"目录没变但新模型永远拿不到参考价"。
6. **同名多源时的选价规则**。模型名先做大小写、provider 前缀、`@日期`、日期后缀、版本后缀归一化；候选按以下优先级排序：
   - 模型家族对应的官方 provider（如 `claude-*` → `anthropic`、`gpt-*` → `openai`、`glm-*` → `zhipuai`）；
   - model id 自带 provider 前缀且 provider 匹配；
   - 其他已知官方 provider；
   - 其余转售商 / 网关。
   同分时取更新时间较新、provider 字典序较小者。价格四舍五入到 3 位小数，与页面输入精度一致。零价不会被隐藏，页面用琥珀色提示"来源标价为 0"。
7. **同步按钮一次完成下载与合并**。选中模型后，参考价显示为一行 `Reference $in / $out / $cache · models.dev · provider`，右侧状态为"已采用 / 同步时更新 / 同步时添加"。点击"同步并保存参考价"后：
   - 参考价有、本地无 → 新增；
   - 两边都有且价格一致 → 忽略；
   - 两边都有且价格不同 → 使用最新参考价覆盖；
   - 本地有、参考价缺失 → 保留原样，不删除（上游可能只是暂时下架了该模型）。
   页面不再提供单模型应用按钮；合并结果通过一次 `PUT /settings` 保存，并 toast 汇总新增/更新/未变数量。
8. **失败保留旧缓存**。下载、解码或写盘失败时返回错误，页面 toast 展示原因；内存与磁盘中的旧缓存不被替换，页面状态行继续显示上次成功同步时间。

## Consequences

- 首次同步需要下载约 5.9 MB（HTTP 压缩后通常更小）；之后靠 ETag 走 304。网络开销只在用户点击时发生。
- 参考价是**公开目录的参考值**，不等于宿主实际上游渠道的结算价；页面显示 provider 名称，同步后会写入已保存单价，仍可在同步后手工调整。
- 同步按钮会直接改写已保存单价，但只发生在用户显式点击时；打开设置页、切换模型、读取建议都不会写价格。
- 同一模型可能有多条报价；当前实现选择一个代表价并在 `providers` 中给出候选数量，不提供逐 provider 选择器。需要精确渠道价时仍可手工填写。
- 缓存体积与"当前模型列表"成正比（实测 16 个模型约 1 KB），与目录规模无关；删除缓存文件无副作用。
- 插件新增了唯一的外部网络出口：`models.dev`。它不携带任何密钥、备注、用量或模型名（GET 无查询参数），仅暴露"本插件在同步价格目录"这一事实。
- 若宿主无外网，功能降级为"无参考价"，不影响手工定价、用量归因与配额拦截。

## Alternatives

- **OpenRouter 目录**：体积更小，但覆盖与单位都不如 models.dev 贴合本插件；放弃。
- **构建期嵌入快照**：零网络但必然过期，且会把数千条模型打进动态库；放弃。
- **打开设置页自动同步**：交互更省一步，但违背插件"无隐式外部请求"的既有边界；放弃。
- **下载后解析整份 JSON 再筛选**：实现简单，但正是需求明确排除的内存放大路径；放弃。
