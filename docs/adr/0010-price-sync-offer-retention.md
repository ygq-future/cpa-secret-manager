# 0010: 参考价同步按报价保留与就近回退

## Context

ADR-0007 的同步规则是"两边价格不同就用最新代表价覆盖"，ADR-0009 把参考价扩展为按优先级排序的多条报价。采用某条报价后，目录里的报价组合会随 provider 上下架变化：原采用的是第三条，同步后它消失，按旧规则会改写成"最合适"的第一条，即使它与已保存单价的价差更大；用户只是想刷新缓存，却被动改了单价。

缓存侧同样存在偏差：ADR-0009 的缓存只在目录内容变化（非 304）且全量刷新时被整体替换；目录未变时 304 分支原样保留旧缓存，宿主移除模型后其缓存项会长期滞留。

## Decision

1. **同价保留**。同步时，已保存单价只要与本次列出的任意一条 `Offer` 的三项价格完全一致，就保持原值并在页面标记为"已采用"，即使它不再是排序第一条。
2. **就近回退**。已保存单价不再匹配任何报价时，改用三项价格绝对差之和最小的剩余报价，避免直接跳到排序第一条造成更大改价；模型完全没有报价时保留已保存单价，页面不再标记已采用。
3. **缓存按模型列表裁剪**。全量同步（`merge: false`）以本次请求的模型列表为准，目录未变更的 304 分支同样裁掉不再请求的模型；`merge: true` 的单模型刷新仍只替换目标模型、保留其他缓存项。
4. **报价展示紧凑化**。下拉报价直接显示 `$输入 / $输出 / $缓存`，不再逐项贴 In/Out/Cache 标签；排序第一条以绿色显示 provider 与 model 表示最合适，不再插入"最合适"前缀；完整报价通过选项与触发器的悬停提示提供。
5. **同步仍显式触发**。读缓存、打开设置页、切换模型都不改价；只有点击同步按钮才写 `app_config.model_prices`。

## Consequences

- 同步不再把用户已采用的同价报价改写成排序第一条；改价只发生在报价集合确实不再包含该价格时。
- 回退写入仍可能改变单价，但幅度是所有候选报价中的最小者；页面 toast 的"更新"计数口径不变。
- 缓存大小跟随当前模型列表，不再随历史模型累积。
- 下拉每项少三分之二的重复标签，输入 / 输出 / 缓存仍以三元色区分。

## Alternatives

- **保留"价格不同即覆盖为排序第一条"**：同价报价会被改写，报价组合变化时可能跳跃改价；放弃。
- **未找到完全匹配时保留原值**：上游调价后单价会长期停在旧值，用户无法察觉；放弃。
- **304 分支继续沿用旧缓存**：模型换季频繁时缓存只增不减；放弃。
- **报价项保留 In/Out/Cache 标签**：每项三份标签挤占宽度，且字段顺序固定；放弃。
