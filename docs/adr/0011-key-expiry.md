# 0011: 密钥过期即时拦截，宿主列表由页面清理

## Context

密钥归属宿主、插件只持有以 SHA-256 摘要索引的元数据。插件的 Web 管理页在用管理密钥做增删改查；但该密钥只存在于页面的管理会话中。插件 Go 运行时在宿主转发管理请求时能看到请求头里的密钥，却不持久化它，也拿不到宿主管理接口的基地址；CPA 的插件回调（`host.*`）只覆盖 HTTP、模型、凭证文件、流与日志，没有管理 API 回调。因此后台无法独立改写宿主密钥列表。

需求是"给密钥设置过期时间，到期自动删除"。如果只把删除放在页面上，页面关闭期间过期密钥仍可继续调用；如果只在拦截器里拒绝，宿主列表里会长期残留一把已失效的密钥。两者都只覆盖一半。

## Decision

1. **过期时间归属插件元数据**：以 Hash Index 索引保存在状态文档 `expirations` 中，值为 RFC3339 UTC 时刻；空值表示永不过期。请求通过 `PUT /expiry` 设置或清除，服务端拒绝过去时刻与非法格式。
2. **拦截器是唯一的执行点**：`request.intercept_before` 在配额检查之前比对 `expires_at` 与运行时时钟，已到期直接返回 `401`、错误码 `key_expired`，不进入上游，也不等待宿主列表被清理。
3. **宿主列表删除由页面执行**：页面每次 `resolve` 都会拿到服务端判定的 `expired` 标记；发现已过期密钥后重新读取宿主 `api-keys`，确认列表未被其他管理端改动，再全量写回剔除过期项，并调用 `/forget` 清掉插件侧备注、过期时间与用量。
4. **不落盘管理密钥**：插件运行时不会为了"无人值守删除"把管理密钥写进状态文档，也不会猜测宿主监听地址去反向调用管理接口。过期执行完全不依赖管理密钥；删除是页面持有凭据时顺带完成的清理。

## Consequences

- 页面关闭时过期密钥立即失效（401），但会留在宿主列表里，直到下一次打开/刷新管理页时被自动移除。
- 所有过期判定使用服务端时钟，浏览器时间偏差只会影响列表时间戳的展示，不会提前或延后拦截。
- 自动清理前会重新读取宿主列表，避免页面拿着过期的本地列表覆盖其他管理端刚做的增删。
- 过期密钥的备注、过期时间与用量在自动删除后一并清除，与手动删除、官方管理端删除的最终状态一致。
