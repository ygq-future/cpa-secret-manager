# 0004: 密钥生成算法与官方管理端 1:1 对齐

## Context

新增代理密钥时需要"自动生成"按钮。官方管理端的实现是（`src/utils/apiKey.ts`）：

```
prefix      = "sk-"
randomLen   = 48
charset     = "ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789"   // 62 个字符
maxUnbiased = floor(256 / 62) * 62 = 248      // 拒绝采样：字节 >= 248 直接丢弃
key         = "sk-" + 48 个均匀分布的 charset 字符（总长 51）
```

拒绝采样的目的是消除 `byte % 62` 引入的取模偏差，使 62 个字符严格等概率。

社区参考实现使用的是 `sk-` + 32 随机字节的十六进制串（总长 67、字符集 16），与官方格式不同，会让"官方面板生成的密钥"与"本插件生成的密钥"出现可肉眼区分的两套形态。

## Decision

1. 生成算法在 Go 侧实现，逐条对齐官方语义：同样的前缀、同样的长度、同样的 62 字符集、同样的 248 拒绝阈值；随机源使用 `crypto/rand`。
2. 生产路径不依赖浏览器 WebCrypto。浏览器的 `crypto.subtle` 只在安全上下文可用（`http://<局域网 IP>:8317` 下不可用），把密钥生成放在页面脚本里会把可用性绑定到部署方式上。
3. 生成逻辑落在独立包中，随机源可注入，以便测试断言：长度恒为 51、前缀正确、字符集受限、`>= 248` 的字节确实被丢弃且不产生短密钥。

## Consequences

- 由本插件生成的密钥与官方管理端生成的密钥形态完全一致，无法从形态上区分来源，便于审计与用户心智统一。
- 生成的密钥只在页面上出现一次，由页面写入宿主管理接口；插件不落盘、不回显历史密钥。
- 若官方未来修改字符集或长度，需要同步更新本实现；该常量在包内单点定义并有测试锁定。
